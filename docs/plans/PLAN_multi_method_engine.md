### 설계 (결정에서 구현으로)

**설정 타입** (`portfolio_types.py`)

- `SlotMethodConfig(method_id, display_name, target_weight, asset_slots)` — 지금의 슬롯 묶음(고정 비중 + 슬롯 전략)을 매매법 하나로. `target_weight` 는 계좌 대비 몫
- `AllocatorMethodConfig(method_id, display_name, target_weight, assets, allocator_id, signal_series=())` — 비중이 바뀌는 매매법. `assets` 는 매매 종목(`AllocationAssetConfig(asset_id, signal_data_path, trade_data_path)`), `signal_series` 는 보유하지 않는 신호용 시세(`SignalSeriesConfig(series_id, data_path)`)
- `PortfolioConfig` 에 `methods: tuple[SlotMethodConfig | AllocatorMethodConfig, ...] = ()` 를 더하고, 기존 `asset_slots` 는 **매매법 하나짜리 실험의 줄임 표기**로 남긴다(기본값 `()`, 둘 중 정확히 하나만 채운다). 엔진은 `asset_slots` 를 `method_id = experiment_name` · 몫 1.0 인 슬롯 매매법 하나로 바꿔 읽는다. **근거**: 기존 실험 4개 · 테스트 15곳의 설정과 `params_json` 출력이 바뀌지 않아 결과 diff 0 을 지키기 쉽다. 모든 생성 호출이 키워드 인자라 필드 순서를 바꿔도 깨지지 않는다(검색 확인)

**배분 규칙 레지스트리** (새 모듈 `src/qbt/backtest/allocator_registry.py`)

- `WeightAllocator` Protocol: `target_weights(data, i, current_date, is_check_day) -> Mapping[str, float] | None` — `data` 는 매매 종목 시세(자산 id 키)와 신호용 시세(series id 키). `None` 은 「목표 변경 없음」. 상태를 가질 수 있다(버퍼존 전략처럼)
- `AllocatorSpec(allocator_id, create, prepare_data, get_warmup_periods)` · `ALLOCATOR_REGISTRY: dict[str, AllocatorSpec]` — `strategy_registry.py` 와 같은 모양. 이 계획서에서 운영 등록은 0개이고, 테스트가 테스트용 규칙을 등록해 쓴다. 실제 규칙은 계획서 ③ 이 등록한다. `get_warmup_periods` 의 뜻은 `ma_window` 와 같다(그 행 수 −1 번째 행부터 판단 가능)

**엔진 흐름** (`portfolio_engine.py` + 새 모듈 `engines/portfolio_methods.py`)

- 매매법마다 장부(`MethodBook`): 현금 · 자산별 주수 · 진입가 · 진입일 · 누적 실현손익 · 신호 상태 · 장부 비용 누적 · 이전 금액 누적 · (비중변동이면) 현재 목표 비중
- 하루의 순서 (기존 A → F 를 매매법 단위로):
  1. **체결**: 전 매매법의 매도 → 매매법 사이 이전 → 전 매매법의 매수. 매도 · 매수는 기존 `execute_orders` 를 매매법 장부에 그대로 쓴다(매도 의도만 / 매수 의도만 두 번 부름 — 한 번 부르는 것과 연산 순서가 같다). 이전은 내주는 쪽의 매도 뒤 현금 안에서만 내주고, 모자라면 받는 쪽에 계획 비율대로 줄여 준다(D34 ③ — 어느 장부도 현금 음수 금지)
  2. **상계**: 자산별로 매매법 주수 변화 Δ 를 모아 `총량 = Σ|Δ|`, `순량 = |ΣΔ|`, `상계 절감 = (총량 − 순량) × 시가 × SLIPPAGE_RATE` 를 계좌에 누적한다. 예: 매매법 A 가 TLT 10,000주 매도 · B 가 6,000주 매수, 시가 100 → 12,000 × 100 × 0.003 = 3,600 (D18 의 예와 같다)
  3. **평가**: 매매법 자본 `E_m = 현금 + Σ 주수 × 종가`(기존 `compute_portfolio_equity`), 계좌 자본 = `Σ E_m + 상계 절감 누적`, 계좌 현금 = `Σ 현금_m + 상계 절감 누적`
  4. **판단**: 매매법마다 신호 의도(슬롯 매매법: 기존 `generate_signal_intents`, 비중변동 매매법: 아래 「배분 변화」) → 예상 상태. 판단일이면 먼저 **매매법 사이 판정**: `몫_m = E_m ÷ Σ E`(상계 절감 제외, D34 ①), 어느 매매법이든 `|몫 ÷ 목표 − 1| > 임계값` 이면 `이전_m = Σ E × 목표_m − E_m` 을 예상 현금에 더하고 그 매매법의 보유 종목 전부를 새 몫으로 맞춘다. 아니면 매매법마다 자기 몫 안에서 기존 판정(진입 · 규칙 변경 자산 제외)
  5. **기록**: 계좌 행(키별) · 상태 로그 행(키별) · 장부 행(매매법별) · 상계 행
- **배분 변화** (비중변동 매매법): 이전 목표 `w0`, 새 목표 `w1`, 보유 `q` 일 때 `w1 = 0 · q > 0` → 전량 청산, `w1 > 0 · q = 0` → 진입(목표 = `E_m × w1`), `w1 > 0 · q > 0 · w1 ≠ w0` → 비중 조정(`E_m × w1` 로 증감). 진입 · 조정 자산은 그날 편차 판정에서 뺀다(D19 · D30). 판정이 걸리면 조정 주문 대신 리밸런싱 주문을 쓴다(같은 목표, 현금 비례 축소가 함께 계산된다)
- `ProjectedPortfolio.entering_assets` 를 `check_excluded_assets`(그날 신호 · 배분 규칙으로 들어오거나 목표가 바뀐 자산 — 판정에서 뺀다)로 이름을 바꾼다. 「진입」만이 아니게 되기 때문이다
- `RebalancePolicy.should_rebalance` · `build_rebalance_intents` 의 `slot_dict` 인자를 `target_weights: Mapping[str, float]` 로 바꾼다 — 비중변동 매매법에는 슬롯이 없다
- **1주 미만 주문**: 처리한 의도는 체결 주수가 0 이어도 상태 로그의 `{키}_executed_intent` 에 그 의도를 적고 `{키}_exec_shares = 0` 으로 둔다. 공식 결과 4개에는 0주 체결이 없어(검사기 위반 0건) 결과가 바뀌지 않는다
