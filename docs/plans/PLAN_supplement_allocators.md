### 엔진이 배분 규칙을 부르는 방식 (2026-10-04 코드 확인)

- `target_weights(data, i, current_date, is_check_day)` 를 **시작일부터 매일** 부른다. `data` 는 {자산 id · series id: 시세}, 실험의 **모든 자산 시세의 공통 거래일로 자른 뒤 워밍업으로 자르기 전** 시세다(`portfolio_engine.py` `_load_portfolio_data_with_common_period` · `_create_books`). `i` 는 그 안의 오늘 행, `is_check_day` 는 월 마지막 거래일 여부
- `None` 은 「목표를 바꾸지 않는다」. 매매법의 첫 목표는 전 종목 0 이다(현금). 같은 비중을 다시 내면 주문이 생기지 않는다(`generate_allocation_intents`) — 그래서 HAA 가 매달 판단을 내도 종목이 바뀔 때만 사고판다(D19)
- 시작일 = 모든 매매법 워밍업 중 가장 늦은 것(`get_warmup_periods` − 1 행). Q-2-2XS 의 SSO · QLD 는 2006-06-21 상장이라, 섞으면 공통 거래일이 2006-06-21 부터다
- 버퍼존 슬롯은 보유 0 이면 `check_buy`, 보유 중이면 `check_sell` 을 하루 한 번 부른다(`generate_signal_intents`). 시작일에는 현금이고 첫 상향 돌파 때 들어간다 — Q-2-2XS 의 SSO 첫 보유 2007-09-24, QLD 2007-08-27(시작 2007-04-09)

### 설계 (규칙에서 구현으로)

**공통**

- 새 패키지 `src/qbt/backtest/allocators/` — 규칙마다 모듈 하나(`haa.py` · `us_weakness_rotation.py` · `ewy_buffer_zone.py`). `strategies/` 와 같은 자리 관용. 등록은 `allocator_registry.py` 가 한다(`strategy_registry.py` 와 같은 모양 — 레지스트리 모듈이 구현을 import)
- **자산 · 시세 id 는 규칙마다 고정**이다. `AllocatorMethodConfig` 에 파라미터 칸이 없어 역할을 id 로 정한다. `create_allocator` 가 설정의 자산 id 집합과 series id 집합이 규칙이 요구하는 것과 **정확히 같은지** 확인하고, 다르면 요구 목록을 담아 `ValueError`
  - HAA: 자산 `spy` · `iwm` · `vea` · `vwo` · `vnq` · `pdbc` · `ief` · `tlt` · `bil`, 시세 `tip`
  - 로테이션: 자산 `vxus` · `shy`, 시세 `spy`
  - EWY: 자산 `ewy` · `shy`
  - TLT 는 Q-2-2XS 와 같은 id `tlt` 다 — 같은 자산 id · 같은 매매 데이터여야 상계된다(D17, 미룬 지적 「같은 데이터 다른 id」)
- 반환 비중은 매매법 자본 대비, 모든 자산 키를 담고(없는 자산 0), 합 1. 0.25 단위 · 0 / 1 이라 float 비교 미룬 지적과 무관하다
- 파생 계산(이동평균 · 월말 행 목록)은 첫 호출 때 한 번 만들어 둔다. 엔진은 같은 `data` 를 매일 넘긴다. 행 j 의 이동평균은 j 이하 행만 쓰므로 미리 계산해도 미래를 읽지 않는다(슬롯의 MA 와 같다)

**HAA** (7.3 — Keller & Keuning 2023)

- 판단: `is_check_day` 인 날만. 그 외 `None`
- 점수 = (1 · 3 · 6 · 12개월 수익률)의 평균. **수익률은 달력 월말 종가 기준** — k개월 수익률 = 오늘(월말) 종가 ÷ k번째 이전 월말 종가 − 1. 월말 = 그 달의 마지막 거래일(데이터의 거래일 기준)
  - **선택과 이유**: 논문 · 공개 신호가 월말 종가로 계산한다. 탈락안은 거래일 수(21 · 63 · 126 · 252일 전 종가) — 구현은 단순하지만 월마다 1 – 2일 어긋나 공개 신호와 대조가 어렵다. 실데이터에서 두 방식의 첫 판단일은 같다(아래 「시작일」)
- 규칙: TIP 점수 ≤ 0 → 방어 자산 100%. 아니면 공격 8개 중 점수 상위 4개에 25% 씩, 그중 점수 < 0 인 자리는 방어 자산으로. 방어 자산 = IEF 와 BIL 중 점수가 높은 쪽
  - 동점은 공격 자산 목록 순서(SPY · IWM · VEA · VWO · VNQ · PDBC · IEF · TLT), 방어는 IEF 가 앞이다. IEF 가 상위 4개이면서 방어 자산이면 비중이 합쳐진다(예 50%)
- 워밍업 253 행(= 12 × 21 + 1). 월말 기준이라 행 수로는 「12개의 이전 월말」을 보장할 수 없다 — 판단일에 이전 월말이 12개 안 되면 `None`(판단 보류)이다. 실데이터에서는 보류가 생기지 않음을 Phase 2 에서 확인한다
- 첫 판단 전에는 현금이다(엔진의 첫 목표 0). 실데이터에서는 5거래일이다(아래 「시작일」)

**미국 약세 감지 로테이션** (7.4)

- 비율 = VXUS 종가 ÷ SPY 종가, 그 200일 단순평균(`FIXED_4P_MA_WINDOW`, `add_single_moving_average` 로 계산 — SMA 단일 구현을 재사용). 비율 > 평균 → VXUS 100%, 아니면 SHY 100%
