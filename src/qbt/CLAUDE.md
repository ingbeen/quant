# qbt 패키지 가이드

qbt는 주식 백테스팅 CLI 도구의 코어 패키지이며 비즈니스 로직만 담당합니다. CLI 인터페이스는 `scripts/`에서 제공합니다 ([scripts/CLAUDE.md](../../scripts/CLAUDE.md)). 도메인별 안내는 `backtest/` · `utils/` 의 `CLAUDE.md` 에 있습니다.

---

## 아키텍처 원칙

### 1. 계층 분리 원칙

비즈니스 로직 계층 (`src/qbt/`):

- 핵심 도메인 로직 구현, 데이터 검증 및 변환
- 예외는 잡지 않고 `raise`로 전파한다 — ERROR 로그는 CLI 계층의 `@cli_exception_handler` 가 남긴다

### 2. 상수 관리 (3계층)

상수 배치 규칙 (사용 범위 기반):

| 사용 범위                        | 배치 위치             |
| -------------------------------- | --------------------- |
| 2개 이상 도메인에서 사용         | `common_constants.py` |
| 도메인 내 2개 이상 파일에서 사용 | `도메인/constants.py` |
| 1개 파일에서만 사용              | 해당 파일 상단        |

예외: 시세 CSV 의 열 이름(`common_constants.py` 「CSV 컬럼명」 절)은 쓰는 파일 수와 관계없이 그 절에 함께 둔다 — 시세 CSV 의 열 구성이 한 곳에서 보여야 한다 (사용자 결정 2026-11-12)

카운트 규칙:

- 제외: 테스트 코드 (`tests/`), 단순 로그 출력
- 포함: 비즈니스 로직 (`src/`, `scripts/`)

원칙: 상수 중복 금지 - 계층 간 중복 정의 시 즉시 통합

상수 명명 규칙 (4가지 접두사): 전역 `~/.claude/rules/python.md` 「네이밍」 참고

내부/출력 분리 원칙:

- 내부 계산: `COL_*` (영문 토큰)
- CSV 출력 헤더: `DISPLAY_*` (한글)
- 저장 직전에 `rename(COL -> DISPLAY)` 적용

### 3. 핵심 패턴

#### CSV 데이터 로딩

- 시세 CSV 는 `utils/data_loader.py` 의 `load_stock_data` 로 읽는다 — 날짜 파싱 · 정렬을 하고, 중복 날짜 · 가격의 결측 · 0 · 음수는 지우거나 메우지 않고 멈춘다(`validate_price_series`). 합성 파일이 같은 폴더의 짝 실물(아래 「시세 파일 이름」)보다 먼저 끝나도 멈춘다 — 두 파일이 quant-data 의 다른 판에서 온 상태다

#### 병렬 처리

- 중앙 집중식: `utils/parallel_executor.py` 의 `execute_parallel_with_kwargs` (ProcessPoolExecutor, 입력마다 키워드 인자 딕셔너리, 입력 순서대로 결과 반환). 워커가 공유하는 큰 데이터는 워커 초기화 때 `WORKER_CACHE` 에 둔다
- spawn 방식(macOS 기본 · Windows) 대응 — pickle 가능한 모듈 레벨 함수 · 클래스 메서드만 쓰고(람다 불가), CLI 스크립트는 `if __name__ == "__main__"` 로 보호한다
- 예외 처리: 병렬 워커에서 예외가 나면 아직 워커에 넘어가지 않은 작업을 취소하고(이미 넘어간 작업은 끝까지 돈다) 전파하여 스크립트 실패 종료
  - 예외를 숨기고 None 반환하는 패턴 금지

병렬 처리 적합성 판단 기준 — ProcessPool 생성/소멸 + pickle 직렬화에는 고정 오버헤드가 있어, 작업의 계산량이 그보다 충분히 클 때만 유리하다:

| 조건             | 병렬 유리                   | 순차 유리                    |
| ---------------- | --------------------------- | ---------------------------- |
| Pool 생성 횟수   | 1~2회 (일괄 배치)           | 다수 (반복 생성/소멸)        |
| 작업당 계산량    | 높음 (Python 루프, 초 단위) | 낮음 (numpy 벡터화, ms 단위) |
| 작업 개수        | 수백 개 이상                | 소수                         |
| 오버헤드 vs 계산 | 오버헤드 << 계산            | 오버헤드 >= 계산             |

## 구현 원칙

qbt 비즈니스 로직 구현 시 준수해야 하는 원칙입니다.

### 상태 비저장

- 계산 함수는 상태를 유지하지 않음
- 모든 입력을 파라미터로 전달
- 순수 함수 스타일 지향
- 상태를 갖는 예외: `BufferZoneStrategy`(돌파 · 유지일 대기), 배분 규칙(첫 호출에 만든 파생 계산), `MethodBook`(매매법 장부)

## 시세 파일 이름 (`storage/stock/`)

이 폴더의 시세는 데이터 저장소 quant-data 가 내보낸 사본이다 — 받을 목록은 `quant_data_files.txt`, 받은 판은 `quant_data_edition.json`. 파일은 늘 전체 기간이다(분석 기간은 분석 단계에서 자른다). 이름은 아래 둘만 읽는다 — 그 밖의 이름은 `ticker_from_stock_path` 가 ValueError 로 멈춘다.

- `{TICKER}_synthetic.csv`: 합성 (상장 전은 대용 지수 · 펀드 · 시뮬레이션, 상장 후는 실물 수정주가). 상장 전 구간의 시가는 진짜 시가가 아니다 — 1배는 그날 종가, 레버리지는 그날 합성 종가에 그날 비용을 더한 값이다(quant-data `docs/research/합성_시세_연장.md` 결정 3)
- `{TICKER}_adjusted.csv`: 실물 수정주가 — 지금은 받지 않는다. 같은 폴더에 있으면 `load_stock_data` 가 합성과 끝날을 맞춰 본다
- 티커에 특수 문자가 있으면 파일 이름에도 그대로 쓴다 (예: `GC=F_adjusted.csv`)

데이터 · 결과 경로는 `common_constants.py` 의 경로 상수가 정본이다.
