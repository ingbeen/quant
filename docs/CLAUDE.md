# docs 폴더 가이드

> 이 문서는 `docs/` 폴더의 문서 작성 규칙(SoT)을 정의합니다.
> 계획서(Implementation Plan) 운영 규칙은 전역 `/impl-plan` 스킬이 SoT입니다 (아래 「계획서 운영 규칙」 참고).
> 프로젝트 전반의 공통 규칙은 [루트 CLAUDE.md](../CLAUDE.md)를 참고하세요.

## 폴더 목적

`docs/`는 QBT 프로젝트의 개발/운영 문서와 변경 계획서(Implementation Plan)를 관리합니다.

## 폴더 구조

```

docs/
├── CLAUDE.md           # docs 관련 규칙(SoT) (이 문서)
├── plans/              # 변경 계획서 저장소
└── research/           # 연구/검증 보고서 저장소

```

### 문서 보관 정책 (중요)

- **아카이브 폴더를 만들지 않습니다.** 과거 문서를 별도 보관소로 옮겨 쌓아두지 않습니다.
- 남길 가치가 있는 과거 이력(결론, 수치, 기각 사유, 폐기 근거)은 `docs/research/`의 해당 보고서 본문에 기록합니다.
- 코드 스냅샷(삭제된 모듈의 함수 목록, 파일 구조 등)은 문서로 복제하지 않습니다. git history가 원본을 보관합니다.
- 역할을 다한 문서는 결론을 보고서에 남긴 뒤 삭제합니다.
- 완료된 계획서(`docs/plans/PLAN_*.md`)는 다른 폴더로 이동하지 않으며, 정리 시점은 사용자가 판단합니다.

### research 폴더 사용 규칙

`docs/research/`는 전략 검증·연구 보고서를 관리합니다. 프로젝트의 판단 근거이자 과거 이력의 기록 위치입니다.

- **파일명은 한글 + 언더스코어**로 작성합니다. 공백과 영문 접두사(`RESEARCH_` 등)를 사용하지 않습니다.
  - 예: `전략_검증_보고서.md`, `QQQ_지연진입_연구.md`
  - 고유명사·티커·전략 ID는 원표기를 유지합니다. 예: `Q2_2XS_QQQ_상관계수_연구.md`
- 한글 파일명 규칙은 **문서(`.md`)에만** 적용합니다. 함께 두는 코드 파일(`.py`)은 [.claude/rules/python.md](../.claude/rules/python.md)의 코딩 표준에 따라 영문 `snake_case`를 유지합니다.

## 계획서 운영 규칙

작성·갱신·Done 판정 절차의 SoT는 **전역 `/impl-plan` 스킬**(`~/.claude/skills/impl-plan/SKILL.md`)입니다.
파일 위치와 네이밍, KST 표기, 필수 구성, Phase 구성 원칙, 스킵·Done 규칙, 근거 승격,
Commit Messages 규칙이 모두 거기 있습니다. 계획서 템플릿도 그 스킬 폴더의 `template.md`를 씁니다.

이 프로젝트 고유의 값(검증 명령, Scope 에 적을 것, 근거 승격 목적지, 커밋 기능명)은
[루트 CLAUDE.md](../CLAUDE.md)의 「계획서 규약 — 이 프로젝트의 설정」 절이 SoT입니다.

> **`docs/plans/` 폴더는 비어도 유지합니다.** 계획서 게이트 훅이 이 폴더의 존재로 규약 채택을 판정하므로,
> 폴더가 사라지면 게이트가 조용히 꺼집니다.

## 스크립트 실행 규칙

`scripts/` 폴더의 스크립트 실행에 관한 규칙은 [루트 CLAUDE.md](../CLAUDE.md#스크립트-실행-규칙)를 참고하세요.
실행 주체(대시보드는 사용자, 나머지는 AI 모델), 소요 시간, 결과 덮어쓰기 주의사항이 그 절에 있습니다.
